## Статусы

Статус отвечает на вопрос: «В каком состоянии сейчас находится заказ?»

В проекте используются следующие статусы:

- `NEW` — заказ создан и ещё не подтверждён.
- `CONFIRMED` — заказ подтверждён.
- `CANCELLED` — заказ отменён.

## Переходы между статусами

| Текущий статус | Действие | Результат |
|---|---|---|
| `NEW` | подтвердить | `CONFIRMED` |
| `NEW` | отменить | `CANCELLED` |
| `CONFIRMED` | подтвердить ещё раз | запрещено |
| `CONFIRMED` | отменить | запрещено |
| `CANCELLED` | подтвердить | запрещено |
| `CANCELLED` | отменить ещё раз | запрещено |

## Правила создания позиции

Позиция заказа — это одна строка в заказе: название товара, количество и цена за единицу.

Для первой версии действуют такие правила:

- `quantity` должен быть больше нуля;
- `unit_price` не может быть отрицательной;
- сумма позиции равна `quantity × unit_price`.

## Почему правила находятся в domain

Эти правила описывают поведение заказа и не зависят от способа его создания или хранения. Поэтому их следует проверять в domain, а не только в HTTP-обработчике. Так правила будут действовать и при вызове логики из фоновой задачи или другого адаптера.

Domain не должен зависеть от FastAPI, SQLAlchemy, PostgreSQL, RabbitMQ или Dishka.
